# Lingxi Workspace v1.0.16

## 修复图片上传保存路径问题

添加图片时，原素材目录因不存在、失效链接、同名文件占用或访问权限问题无法创建或写入，会自动尝试应用数据目录内的备用位置。保留原目录和已有文件，不自动删除目录冲突。

- 原位置：`content/<项目ID>/materials/`。
- 备用位置：`content/material-storage/<项目ID>/`。
- 实际完整路径写入 `content/content.sqlite3` 素材记录的 `payload.sourcePath`。图片预览、WorkBuddy 整理、去重和删除使用记录中的路径。
- 两处保存位置都不可用时，显示中文原因和错误码，提示导出诊断日志。

## 素材失败诊断与导出

素材保存失败时，记录目标路径、错误码、失败阶段，以及各级目录是否存在、是否为链接、链接目标、实际路径和系统写权限检查结果；备用目录保存成功也会记录实际路径。

用户在“设置 → 排障与本地数据 → 导出诊断日志”保存 JSON 文件后，可直接发给技术支持，无需远程操作电脑。报告包含近期素材日志、当前目录快照、应用版本及系统信息，不包含图片内容、文章正文或账号凭据。

日志通常保存在应用数据目录的 `diagnostics/materials.log`。目录不可写时尝试系统临时目录，再失败则保留内存记录。写权限检查不保证实际写入成功，无法判断的结果标记为 null。升级前未记录的故障需要在新版本中重试才能采集。

## Lingxi Workspace 白屏诊断工具

- 独立启动提示页可在界面脚本、React 或 preload 加载失败时显示错误编号和复制诊断入口。
- 记录启动超时、页面加载失败、主程序异常、渲染进程退出及启动期间的 GPU 异常。
- 原生错误弹窗提供复制诊断信息、重新加载界面或重新启动应用。
- Windows 提供“兼容模式重启”，使用软件渲染并记住设置。
- 启动日志保存在应用数据目录的 `diagnostics/startup.log`，支持轮转、临时目录回退及内存记录。
- Windows Store 校验增加包内启动资源检查、实际安装激活和界面就绪验证。

## 验证方式

本地已通过 213 项自动测试、类型检查、应用及 CLI 构建、Go 测试，以及以下 7 个启动场景和素材诊断导出界面测试。真实 Windows/MSIX 构建与安装校验由 GitHub Actions 执行。

- `npm run typecheck` 和 `npm test`：类型检查、素材保存恢复、目录诊断、持久日志和启动故障处理测试。
- `npm run test:diagnostics`：验证备用目录保存、取消导出、保存失败和界面成功导出。
- `npm run test:startup`：验证正常启动、缺少界面脚本、缺少 preload、缺少 HTML、React 异常、项目数据损坏和渲染进程退出。
- Windows/MSIX 实际环境的结果以 GitHub Actions 为准；诊断工具用于采集原因，不代表所有白屏原因均已修复。
