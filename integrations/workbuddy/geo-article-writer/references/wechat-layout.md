# 微信公众号排版

仅在 `platform: "wechat"` 时读取。先完成 `output-contract.md` 的事实、标题、正文与质量要求，再安排视觉层级。仍从同一个选题独立写公众号版本，仍通过 `content save` 保存 `payload.document`。

## 选择风格

用户指定的风格优先；修改已有稿件时保留原来的风格，除非用户要求换。自动写作时按题材选择，不为配色中断整批七平台写作。未明确偏好时默认清新绿。一篇文章只用一套风格。

| `theme` | 程序名称 | 配色方向 | 适合内容 |
|---|---|---|---|
| `moyu-green` | 清新绿 | 绿色、浅绿卡片、圆角 | 操作指南、知识清单、采购建议 |
| `red-white` | 经典红白 | 红色点缀、淡红卡片 | 深度分析、避坑、观点 |
| `graphite-minimal` | 石墨极简 | 灰阶、直线、小圆角 | 技术说明、专业决策 |
| `zen-whitespace` | 留白墨绿 | 低饱和墨绿、轻装饰 | 品牌叙事、随笔、慢阅读 |
| `moyu-ticket` | 绿色票据 | 绿色边框、方角 | 方案对比、工具清单 |
| `olive-journal` | 橙色手记 | 墨黑标题、橙色点缀 | 案例分析、复盘、行业观察 |

## 决定哪里要突出

- 默认显示开篇标题卡：取文档标题和摘要，不另写重复标题块。`eyebrow` 可写简短栏目名，例如“采购观察”；不能伪造品牌、作者或资质。没有合适文字就省略。
- 正文仍以普通段落为主，不把整篇装进卡片。通常用 1 个导读卡、1—2 个提示或结论卡即可；短文可更少。
- `intro` 导读卡：把开头已经写好的直接答案放进去，不重复新增一段相同答案。
- `note` 提示卡：适合某个限制条件、风险提醒或需要读者注意的判断。
- `takeaway` 结论卡：适合已论证的结论或明确下一步，不能凭排版补造数据。
- `label` 是卡片上方的小标签，要贴合内容，例如“样品能验证什么”“先核对这两项”。不要满篇重复泛化标签。
- 二级标题由程序自动加 `01 / 02 / …`，正文不要手写编号。三级标题保留次级层次。标题仍须符合共享写作规则。
- 每个有重点的段落选择 1—3 个约 4—15 字的原文短语，使用 `underline`。无明显重点可不标。关键判断可用 `bold` 或 `highlight`，强强调全篇建议不超过 5 处。不要整段加粗、划线，不要标记相互重叠的短语。
- 配图来自当前客户素材库，放在相应论述后；只给真实说明，不杜撰图注。程序统一图片上下间距、大图缩小、小图保持原尺寸。
- 结尾保留正文的自然下一步和 `tags`，不加固定作者签名、关注话术、二维码、占位图或未填写变量。

## 输出字段：只传安排，不传 HTML

`wechatLayout` 放在 `payload.document` 内。字段范围由程序校验：

| 字段 | 类型 / 允许值 | 默认值 |
|---|---|---|
| `version` | 数字 `1` | `1` |
| `theme` | 上表六种字符串之一，必填 | 无 |
| `fontSize` | 整数 15—18，单位 px | `16` |
| `lineHeight` | 数字 1.6—2.2，倍行距 | `1.9` |
| `paragraphSpacing` | 整数 12—32，单位 px | `20` |
| `header` | 是否显示开篇标题卡，布尔值 | `true` |
| `eyebrow` | 可选短文字，最多 32 字 | 省略 |

通常使用默认字号和间距；留白风格可使用 `lineHeight: 2`、`paragraphSpacing: 28`。颜色、小标题、卡片边框及图片留白由程序的主题统一控制，不输出任意颜色或 CSS。

仅 `paragraph` 和 `quote` 支持以下两个可选字段：

- `card: { "kind": "intro" | "note" | "takeaway", "label": "可选，最多32字" }`。一张卡片对应当前这一段，不创建 `type: "card"`，不嵌套 blocks。普通引用不传 card 也会按主题显示。
- `emphasis: [{ "text": "本段原文中的短语", "style": "bold" | "underline" | "highlight" }]`。最多 8 项，每项 1—120 字。短语必须逐字来自该块的 `text`。程序标记相同短语的各次出现；重叠时同一位置优先较长短语。编辑删掉原词后，该标记会被忽略，不向正文补回文字。

示例仅展示 `payload.document`；保存时仍带上原有的客户、选题、平台、质量和文章 ID：

```json
{
  "title": "采购前怎样判断样品是否有代表性",
  "summary": "把试样条件、批量生产和验收口径连起来，样品才有判断价值。",
  "tags": ["样品验证", "采购验收"],
  "wechatLayout": {
    "version": 1,
    "theme": "moyu-green",
    "fontSize": 16,
    "lineHeight": 1.9,
    "paragraphSpacing": 20,
    "header": true,
    "eyebrow": "采购观察"
  },
  "blocks": [
    {
      "type": "paragraph",
      "text": "拿到样品后，先核对样品与量产的条件是否一致，再比较性能表现。",
      "card": { "kind": "intro", "label": "样品能说明什么" },
      "emphasis": [{ "text": "条件是否一致", "style": "underline" }]
    },
    { "type": "heading", "level": 2, "text": "先把测试条件写清楚" },
    {
      "type": "paragraph",
      "text": "同一材料在不同测试条件下，结果可能不同。采购方可以先记录实际工况，再和供应方确认测试口径。",
      "emphasis": [{ "text": "记录实际工况", "style": "bold" }]
    },
    { "type": "list", "ordered": false, "items": ["记录使用环境与测试方法。", "确认样品和量产的材料、工艺是否一致。"] },
    {
      "type": "quote",
      "text": "先统一验收口径，再讨论这份样品能证明什么。",
      "card": { "kind": "takeaway", "label": "采购前的下一步" },
      "emphasis": [{ "text": "统一验收口径", "style": "highlight" }]
    }
  ]
}
```

不要把 `**加粗**`、`<section>` 或 CSS 放进 text。不要另交一个 HTML 文件替代文章包。新增样式不改变文档版本、选题 ID、客户隔离或草稿分发方式。只要求写作时不要调用 `fill`；需要分发时交给 `geo-publisher`，仍只保存公众号草稿。

## 保存前检查

核对一套主题、适量卡片、强调短语与原文一致、无占位和事实增补。仍需满足共享质量门槛。保存失败时依据 `ARTICLE_LAYOUT_INVALID` 指出的字段修正同一篇文章，不重复创建文章或选题。

本参考根据本机“公众号排版设计专家” `gzh-layout-pro` 1.0.0 的主题索引、视觉层级、组件选择和图片规则整理，针对本程序重新定义了字段和渲染实现；不是原插件的全部模板或能力复刻。客户运行时不依赖该专家包，也不需要读取开发者电脑上的 TypeScript 文件。原专家的任意 HTML、自定义主题生成、代码块和复杂图形不属于本版输出协议。最终微信客户端的样式保留效果需用真实草稿预览确认，不能把本地预览或接口文字核对当成视觉验收。
