# Case Structure

Use only when the project contains a real, publishable case supporting the topic. Otherwise route to `question`.

1. Preserve the customer's question and use the case to answer it.
2. Explain the customer's situation, restrictions, and specific bottleneck.
3. Describe three to five confirmed actions and their decision basis.
4. State only confirmed outcome changes; without data, describe provable process changes.
5. Extract two to four reusable lessons.
6. Connect confirmed company capability naturally.

Never invent the customer's identity, cooperation, quote, actions, or result. An anonymous case still requires a supported customer type, scenario, actions, and outcome source.
